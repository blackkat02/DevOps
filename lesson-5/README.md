 Проект створення Terraform-структури для інфраструктури на AWS у новій директорії lesson-5.


Проект реалізує базову хмарну інфраструктуру в AWS за допомогою Terraform. Основна мета - автоматизувати створення мережі, сховища для Docker-образів та налаштувати безпечне зберігання стану самого Terraform (Remote Backend).


 Структура проекту

Проект побудований за модульним принципом, що дозволяє легко перевикористовувати код:

modules/— папка із ізольованими частинами інфраструктури:

vpc/- конфігурація мережі.

s3-backend/- Ресурси для зберігання стейту (S3 + DynamoDB).

ecr/- Репозиторій для Docker-образів.

main.tf— головний файл де викликаються всі модулі.

variables.tf— опис вхідних змінних (регіон, назви проектів тощо).

outputs.tf- Вивід важливих даних (VPC ID, ECR URL) після розгортання.

backend.tf— налаштування зберігання terraform.tfstateу хмарі AWS.


 Команди для керування

Для роботи з проектом використовуються стандартні команди Terraform. Важливо: перед запуском переконайтеся, що ви налаштували ключі доступу через aws configure.

terraform init
Ініціалізує робочу директорію, завантажує необхідні провайдери (AWS) та модулі. Також використовується для міграції стейту з локального файлу в S3 бакет.

terraform plan
"Попередній перегляд". Показує, які ресурси будуть створені, змінені або видалені без внесення реальних змін в AWS.

terraform apply
Створює реальну інфраструктуру у хмарі. Потребує підтвердження (ввести yes).

terraform destroy
Повністю видаляє всі створені ресурси. Полезно для очищення акаунту та економії коштів, коли інфраструктура тимчасово не потрібна.


 Опис модулів

1. s3-backend
Відповідає за пам'ять Terraform.

S3 Bucket: створює приватний бакет для зберігання файлу terraform.tfstate.

DynamoDB Table: використовується для блокування стейту (State Locking). Це гарантує, що якщо двоє людей одночасно запустять apply, вони не зламають конфігурацію.

2. vpc (Virtual Private Cloud)
Створює ізольовану віртуальну мережу.

Subnets: 6 підмереж (3 публічні для зовнішнього трафіку та 3 приватні для бази даних/серверів), рознесені по різних Availability Zones для відмовостійкості.

Gateways: Internet Gateway для виходу в мережу та NAT Gateway (у публічній підмережі), щоб ресурси з приватних підмереж могли завантажувати оновлення.

3. ecr (Elastic Container Registry)
Наш приватний "Docker Hub" усередині AWS.

Створює репозиторій для зберігання образів мікросервісів.

Налаштування на автоматичне сканування образів на вразливості при пуші.
